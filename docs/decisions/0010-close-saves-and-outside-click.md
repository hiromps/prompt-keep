# 0010: 編集を閉じる操作は「保存してから閉じる」に揃え、外側のクリックは押した位置と離した位置で判定する

- 日付: 2026-10-01
- 状態: 採用
- 関連: [0008](0008-prompts-layout-owns-data.md)

## 背景

「PC でメモを編集中、本文をドラッグで選択したままカーソルをメモの外へ出すと、メモが閉じて
入力内容が保存されないことがある」という報告。

原因は編集モーダル（`<dialog>.showModal()`）の背景クリックの判定だった。
`click` イベントは **ボタンを押した要素と離した要素の共通の祖先** に届く。本文（textarea）で押して
背景で離すと、共通の祖先である `<dialog>` 自身が target になり、`e.target === dialog` という
背景クリックの判定に一致してしまう。実測したイベントの順は次のとおり。

```
pointerdown → textarea / pointerup → dialog / click → dialog / close → dialog
```

しかも背景のクリック・Esc・左上の戻るは「キャンセル」（保存せずに閉じる）扱いだったので、
誤って閉じた瞬間に書きかけが消えていた。

調べる中で、同じく書きかけが消える経路が他にも見つかった。

- 保存中に通信が切れると、`startTransition` の中の例外が error boundary まで飛び、
  画面ごと（モーダルごと）エラー画面に置き換わる
- 「保存」を押した後、保存が終わるまでに打った文字は保存されないまま閉じる
- Esc を続けて 2 回押すと、2 回目の `cancel` はブラウザがキャンセル不可で送ってくる
  （close watcher の乱用防止）。`preventDefault()` が効かず、こちらの手順を通らずに閉じる
- ブラウザの戻るなどで一覧のビューが変わり、編集中のカードが一覧から外れると、
  モーダルごとアンマウントされる
- 他の端末の更新で一覧の並びが変わると React がカードの DOM を動かす。モーダルはカードの中に
  あったので、そのとき文書からいったん外れて top layer（モーダル）でなくなる

## 決定

### 1. 外側のクリックは「押した位置と離した位置の両方が外側」のときだけ

`src/components/outside-click.ts` に判定をまとめ、編集・共有ダイアログ、LP のデモ、クイック入力で使う。

- `<dialog>` の背景: `pointerdown` と `pointerup` の target が両方 dialog 自身で、
  `click` の target も dialog 自身のとき（`useBackdropClick`）。ダブルクリックの 2 回目
  （`detail > 1`）は拾わない（カードのダブルクリックで、開いた直後に閉じてしまうため）
- クイック入力の外側: 同じく押した位置と離した位置で判定し、外側で文字をドラッグ選択しただけ
  なら閉じない（`useClickOutside`）。タッチでスクロールしただけなら `click` が来ないので閉じない

### 2. 閉じる操作はすべて「変更があれば保存 → 保存の完了 → 閉じる」

背景のクリック・Esc・左上の戻る・「閉じる / 保存」ボタン・Ctrl+Enter（⌘+Enter）は同じ入口
（`finish("save")`）を通る。変更を捨てるのは「キャンセル」だけ（変更があるときだけ表示）。
クイック入力も同じで、書いて外を触れば保存される（Keep と同じ）。

- 変更が無ければ保存しない。開いた時点の内容と比べる（`isDraftChanged`）ので、
  開いている間に他の端末で更新されても、ここで触っていなければ上書きしない
- 保存中は入力を止め（readOnly）、重ねた閉じる操作は無視する（二重保存しない）
- 保存に失敗したら閉じずにエラーを出す。ブラウザが先に閉じていた（Esc の連打）ら開き直す
- ブラウザが自分で閉じた（`close` イベントがこちらの手順の外で来た）ときも、保存の流れに乗せる

### 3. 保存する値は ref から読み、打ちかけのタグも含める

入力のたびに同期で書き換える ref（`latest`）を保存の唯一の入力にする。state は描画用で、
非同期処理の続きやアンマウント時には古い値を掴むことがある。タグ欄で Enter を押す前の
文字（`pendingTag`）も確定済みとして保存する（Esc で閉じると blur を通らないため）。

### 4. 消える経路をふさぐ安全網

- Server Action の呼び出しは `callAction`（`src/lib/errors.ts`）を通し、通信断などの例外を
  共通形式のエラーに直す（error boundary へ飛ばさない）
- 閉じる操作を通らずにアンマウントされたら、未保存の変更を裏で保存する
- 未保存のままタブを閉じる・再読み込みするときは `beforeunload` で確認を出す
- 編集・共有ダイアログは `createPortal` で body 直下に出す（カードの DOM が動いてもモーダルのまま）

## 理由

- 「押した位置で判定する」は、ダイアログの背景クリックでよく使われる方式（MUI の Dialog など）。
  テキストの選択は必ず中で押して始まるので、選択の途中で外へ出ても閉じない
- 閉じる操作が 5 種類ある中で「どれが破棄か」を覚えさせるのは誤操作のもと。
  閉じれば保存、捨てるのは明示的な「キャンセル」だけ、にすると書きかけが黙って消えることがない
- 「保存 → 完了 → 閉じる」の順にすると、保存に失敗したときに内容とエラーを見せる場所が残る

## 却下した代替案

- **外側のクリックで閉じる処理をやめる**: Keep の基本の操作（外を触れば閉じる）が失われる
- **`pointerdown` だけで閉じる**（押した瞬間に判定）: クイック入力では、タッチで画面に触れて
  スクロールしただけで閉じてしまう
- **入力のたびに自動保存（debounce）**: 書くたびに `revalidatePath` で一覧ごと再描画され、
  更新日時順で並びも動く。「キャンセル」も成り立たなくなる。今回は閉じるときの保存と安全網で足りる
- **閉じてから裏で保存する（楽観的）**: 閉じた後に失敗すると、内容とエラーを見せる場所が無い

## 影響

- Esc・背景のクリック・左上の戻るの意味が「破棄して閉じる」から「保存して閉じる」に変わる
- クイック入力の「閉じる」（破棄）は、入力があるときは「キャンセル」（破棄）と「保存」に分かれる。
  外側のクリック・Esc は保存して畳む
- 同時編集は、従来どおり最後に保存した方が勝つ（上書きの検出はしていない）
