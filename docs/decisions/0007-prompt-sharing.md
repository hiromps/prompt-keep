# 0007. プロンプトの共有はリンク＋QRのみ、トークンは別テーブルで持つ

- ステータス: 採用
- 日付: 2026-09-04
- 関連: [0002](0002-server-only-data-access-rls-as-defense.md) / [0005](0005-prompt-data-model.md) / [0006](0006-service-role-grants.md)

## 背景

「QRコード（リンクも併せて）を発行して、ペアリングしたい相手とシェアしたい
プロンプトを簡単に共有できるようにしたい」という要望。目の前の相手にスマホで
読み取ってもらう場面を想定している。

共有・チーム利用は当初スコープ外にしていた（[mvp-scope](../mvp-scope.md)）。
これはその判断を意図的に覆すもの。ただし覆すのは**1枚のプロンプトを渡す**ところまでで、
チーム・権限分け・共同編集は引き続きスコープ外に置く。

要件の確認結果:

- 共有範囲: **リンクを知っている人なら誰でも（ログイン不要）**
- 受け取り側: **閲覧とコピーのみ**
- 取り消し: **いつでも手動で停止**（期限切れは設けない）

## 決定

### 1. リンクは「推測不可能なトークン」1本で守る

`/s/<token>` を認証なしで公開する。`token` は Node の `randomBytes(24)` を
base64url にした32文字。パスワードも期限もなく、**トークンの推測不可能性が
アクセス制御そのもの**になる。

そのため:

- 発行は必ずサーバー側（`src/features/prompts/actions.ts`）。連番・短縮IDは使わない
- 存在しない / 停止済み / ゴミ箱行き は**すべて同じ 404**。区別を返すと、
  停止済みリンクの存在を確認できてしまう
- ページは `noindex, nofollow` かつ `referrer: no-referrer`。
  検索に載らないこと、本文中のリンクを踏まれてもリンク自体が Referer で
  外部へ渡らないことを担保する

### 2. トークンは `prompts` の列ではなく `prompt_shares` テーブルに置く

`prompts.share_token` として持つ方が単純に見えるが、採らなかった。

- **停止したリンクを復活させない**: 停止は `revoked_at` を立てるだけで行は残し、
  再共有では必ず新しいトークンを発行する。列で持つと「停止＝NULL、再共有＝
  同じ列に入れ直す」実装に流れやすく、いったん回収したはずのリンクが
  黙って生き返る事故が起こる
- **公開した履歴が残る**: 「これ、前に誰かに渡したっけ？」に後から答えられる
- `prompts` は「本人のデータ」という意味を保てる

有効な共有は1プロンプトにつき1本まで（`revoked_at IS NULL` の部分ユニーク
インデックス）。「共有」を連打してもリンクが増えないことを DB 側で保証する。

### 3. 公開クエリは専用ファイルに隔離し、返す列を閉じる

`src/features/prompts/shares.ts` の `getSharedPrompt(token)` が唯一の入口で、
`title, body, tags, updated_at` しか返さない。`owner_id` はもちろん `id` も返さない
（共有していない他の行を推測する手掛かりになる）。

このアプリで**ログインなしに DB の中身を返す経路はここだけ**なので、
ファイル冒頭にその旨を書いて、あとから列を足されないようにしている。

### 4. アーカイブは共有し続け、ゴミ箱は止める

- アーカイブ = 持ち主の整理都合。「共有をやめた」という意思表示ではないので配信を続ける
- ゴミ箱 = 消すつもりのもの。`deleted_at IS NOT NULL` なら 404 にする。
  復元すれば同じリンクがまた開く（共有行は消していないため）

### 5. ダイアログを開いただけでは公開しない

未共有のプロンプトでは「共有リンクを作成」を押すまで `prompt_shares` に行を作らない。
発行済みなら開いた時点でリンクを取り直す（サーバー側は冪等）。
「様子を見るために開いたら公開されていた」を避けるため。

## 影響

- 新テーブル `public.prompt_shares`（`20260904000002_prompt_shares.sql`）
- 新ルート `/s/[token]`（`(protected)` の外。認証しない）
- `src/app/loading.tsx` を `src/app/(protected)/loading.tsx` へ移動。
  ルート直下に置くと全ルートが Suspense 境界に包まれ、シェルが先に flush される結果
  `notFound()` を呼んでも **HTTP 200 が返っていた**（実測）。404 を本物の 404 にするため
- `listPromptsByOwner` が有効な共有を LEFT JOIN して `share_token` を返す
  （カードに「共有中」の印を出すため）
- QR は `qrcode` パッケージでサーバー生成し、PNG の data URL としてダイアログへ渡す。
  クライアントバンドルに QR ライブラリを載せない

## 代替案と却下理由

| 案 | 却下理由 |
|---|---|
| ログイン必須の共有（相手のアカウントを指定） | 相手にアカウントを作らせる。目の前でQRを読ませる用途に対して重い |
| 有効期限つきの署名リンク（JWT 等） | 期限を決められない用途。「いつでも停止」の方が要件に合い、失効を DB 1行で確認できる |
| `prompts.share_token` 列 | 上記2の通り、停止したリンクの復活を招きやすい |
| QR をクライアントで生成 | 生成のためだけにライブラリをバンドルへ載せる。URL はどのみちサーバーが知っている |
| 共有ページで編集も許可 | 要件が「閲覧とコピー」。書き込み経路を増やすと認可の面が広がる |
