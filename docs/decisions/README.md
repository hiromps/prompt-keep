# Architecture Decision Records (ADR)

- **目的**: 後から「なぜこうなっているのか」を辿れるように、重要な設計判断とその理由・却下した代替案を記録する。
- **対象読者**: 将来の自分・このスターターから派生したプロジェクトの開発者・AIアシスタント。
- **記入方法**: 設計に影響する判断をしたら `NNNN-短いタイトル.md` を追加する。テンプレート:

```markdown
# NNNN: タイトル

- 日付: YYYY-MM-DD
- 状態: 採用 / 廃止 / NNNN で置換

## 背景
## 決定
## 理由
## 却下した代替案
## 影響
```

一度書いた ADR は書き換えず、判断が変わったら新しい ADR で置換する。
