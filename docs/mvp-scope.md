# MVP Scope

- **目的**: 最初のリリースに「入れるもの / 入れないもの」を固定し、スコープクリープを防ぐ。
- **対象読者**: 開発者本人・AIアシスタント。
- **記入方法**: product-brief.md 確定後に記入。追加要望は原則「入れないもの」→ 次バージョン候補へ。

---

## MVP に入れるもの（Must）
| # | 機能 | 対応する課題 | 状態 |
|---|---|---|---|
| 1 | プロンプトの作成・編集・削除（タイトルは任意） | 貯める場所がない | 実装済み |
| 2 | タグ付けとサイドバーでの絞り込み | 分類できない | 実装済み |
| 3 | タイトル・本文・タグを横断する検索 | 見つからない | 実装済み |
| 4 | 本文のワンクリックコピー | 使うたびに選択・コピーが面倒 | 実装済み |
| 5 | ピン留め | よく使うものが埋もれる | 実装済み |
| 6 | アーカイブ | 使わなくなったが消したくない | 実装済み |
| 7 | ゴミ箱（論理削除・復元・完全削除） | 誤削除が怖い | 実装済み |
| 8 | 1件のプロンプトをリンク + QR で共有（閲覧・コピーのみ、いつでも停止） | 目の前の相手にプロンプトを渡す手段がない | 実装済み |

## MVP に入れないもの（明示的に除外）
| 機能 | 除外理由 | 再検討タイミング |
|---|---|---|
| カードの色分け | タグで代替でき、色は検索できない | タグだけで足りなくなったら |
| ラベルの改名・削除（ラベル管理画面） | タグを `text[]` で持っているため全行更新が必要（[ADR 0005](decisions/0005-prompt-data-model.md)） | タグの整理が苦痛になったら |
| インポート / エクスポート | 移行対象のデータを持ち込まない方針にしたため | 別環境へ移す必要が出たら |
| チーム利用・権限分け・共同編集 | 自分専用に絞る。渡すのは「1枚を読み取り専用で」までに留める（[ADR 0007](decisions/0007-prompt-sharing.md)） | — |
| 共有リンクの有効期限・パスワード | 「いつでも手動で停止」で要件を満たす。期限は決めようがない | 配った先を追えなくなったら |
| ゴミ箱の自動削除 | cron が無い。手動削除で足りる | 定期実行の仕組みを入れるとき |
| 埋め込み+ベクトル検索 | 件数に対して過剰。文字列一致で足りる | キーワードで拾えない検索が増えたら |

## 有効化する Optional modules
`project.config.ts` の `modules` と一致させること。

- [x] admin（スターター由来のロールゲート検証サンプル。個人利用では不要だが、消すと E2E も直す必要があるため残置）
- [x] search（クライアント側の文字列検索として実装）
- [ ] payments / email / organizations / その他

## リリース判定チェックリスト
- [ ] Must 機能がすべて動作する
- [ ] `pnpm check`（typecheck / lint / test / build）が通る
- [ ] E2E が通る
